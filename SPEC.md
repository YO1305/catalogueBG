# ТЗ: BAHMAL Catalog — интерактивный онлайн-каталог тканей

Версия 1.1 · 23.10.2026 (добавлено: PSD-мокапы, масштаб до ×10 на каждом макете, свободный ввод плотности/ширины, свои коллекции, типы тканей и изделия) · Владелец: отдел маркетинга BAHMAL HOME
Файл кладётся в корень репозитория как `SPEC.md`. Cursor работает строго по нему.

---

## 0. Суть в трёх предложениях

1. Дизайнер загружает **оригинальный файл рисунка ткани** и заполняет карточку на русском. Система **сама** переводит текст на EN и UZ и **сама** накладывает рисунок на реалистичные фото-шаблоны изделий (спальня с кроватью, курпача в комнате, полотенце в ванной и т.д.).
2. Менеджер собирает **отдельные каталоги-подборки** под клиента или рынок («Курпача 2026», «Евро — сатин», «Fashion для Польши»). У каждого своя ссылка, и в каждом показываются **только нужные ткани и только нужные макеты** (в каталоге курпачи нет кроватей).
3. Клиент открывает ссылку и видит **журнал с перелистыванием страниц** (как flipbook), но интерактивный: на странице 2–3 дизайна, нажал на дизайн — открылась ткань (реальное фото рисунка с зумом), макеты, характеристики и кнопка «Запросить образец».

| Слой | Технология | Почему |
|---|---|---|

| Хостинг | Vercel | Как в CRM |

| PSD-мокапы | `ag-psd` (разбор PSD в Web Worker) + WebGL2; запасной движок — Photopea API в скрытом iframe | Загружаем готовый мокап, система сама вставляет рисунок в smart object |

### Справочники — пополняются самими пользователями (дизайнер, менеджер, админ)
```ts
collections/{id}  = { name: {ru,en,uz}; slug: string; order: number; active: boolean; catalogSlug?: string /* авто-каталог коллекции */ }
fabricTypes/{id}  = { name: {ru,en,uz}; suggestedProductTypes: string[]; order: number; active: boolean }
productTypes/{id} = { name: {ru,en,uz}; suggestedFor: string[] /* fabricTypes */; order: number; active: boolean }
finishes/{id}     = { name: {ru,en,uz}; order: number; active: boolean }  // только подпись; крашение задаёт раздел «Однотонные»
```
- Стартовые отделки: Крашение, Печать, Отбелённая, Пряжа крашеная. Новые добавляются прямо из формы ткани («＋ Добавить новый…») или в Настройки → Отделка.
- Стартовые коллекции: Внутренний рынок, Евро коллекция, Fashion. Стартовые типы ткани: поплин, сатин, страйп-сатин, фланель, бязь, вафельное полотно, махра, дак, ткань для курпачи, твил, жаккард, дамаск (страйп-сатин, жаккард и дамаск — с признаком «тканый рисунок», 5.7.6).
- `name.en/uz` переводятся автоматически при создании (раздел 4), правятся вручную.
- Удалить элемент справочника, который используется, нельзя: только «скрыть» (`active:false`). Удаление пустого — админ.
Стартовый набор: КПБ, пододеяльник, простыня, наволочка, одеяло/покрывало, наматрасник, **курпача**, декоративная подушка, полотенце, кухонное полотенце, скатерть, салфетки, прихватка/рукавица, пижама/халат, рулон ткани (всегда доступен).

### Правила доступа (Firestore Rules)
- `fabrics`, `catalogs`: чтение публичное только для `status == published/live`; запись по ролям.
- `templates`, `productTypes`: чтение всем, запись только админу.
- `leads`: создание всем (через серверную функцию с rate-limit), чтение менеджеру и админу.

## 4. Перевод RU → EN / UZ

> **Обновлено по решению заказчика:** тексты каталога (название, подзаголовок) и дизайна (название, состав, отделка, описание) дизайнер заполняет **сам на каждом языке** через переключатель RU / EN / UZ в начале формы. Автоперевод при публикации дизайна и при создании каталога отключён, чтобы не перезаписывать ручной текст. Если EN или UZ не заполнен, журнал показывает русский текст. Автоперевод ниже остаётся только для справочников (коллекции, типы ткани, изделия), запасной словарный перевод сохраняет заглавную букву.

**Когда:** при сохранении карточки ткани или каталога и по кнопке «Перевести заново».
**Как:** серверная функция `POST /api/translate`. На вход идут поля RU, на выходе JSON `{en:{...}, uz:{...}}`.

**Системный промпт (зашить в код):**
```
You are a professional textile translator for BAHMAL HOME, a textile manufacturer from Uzbekistan.
Translate Russian product copy into English (and Uzbek Latin script). Keep it concise, B2B-catalog style, British spelling.
STRICTLY use this glossary; never translate these terms differently:
поплин=poplin; сатин=sateen; страйп-сатин=stripe sateen; фланель=flannel; бязь=calico; вафельное полотно=waffle fabric;
махра=terry; дак=duck canvas; ткань для курпачи=kurpacha fabric; курпача=kurpacha (traditional Uzbek floor mattress, explain only on first mention);
КПБ=bed linen set; пододеяльник=duvet cover; простыня=flat sheet; простыня на резинке=fitted sheet; наволочка=pillowcase;
плотность=density (g/m²); ширина=width (cm); раппорт=repeat; набивной=printed; гладкокрашеный=solid-dyed; абр/икат=ikat (abr);
сюзане=suzani; не линяет=colourfast.
Brand and design names in «» are transliterated, not translated (Лаванда → Lavanda).
Return ONLY valid JSON matching the input keys.
```
- Глоссарий хранится в Firestore (`settings/glossary`) и редактируется в админке. Промпт собирается из него.
- Если дизайнер правил перевод руками, ставится `translationLocked` и автоперевод больше не трогает это поле.
- Рядом с переводом есть кнопка «Проверить»: выделяет слова, которых нет в глоссарии, но которые похожи на термины.

## 5. Макеты на фото-интерьерах

**Основной и единственный формат шаблонов сейчас — ZIP-пакет (раздел 5.7).**  
Разделы **5.1–5.6 (PSD-мокапы, `/admin/lab/psd`, этап 3a)** **отложены** и не развиваются до отдельного решения.  
**Раздел 5.4 (масштаб ×0.1–×10, сдвиг, поворот на каждом макете и зоне) не отложен** — он обязателен и для ZIP-шаблонов (`engine: "uvgrid"`).

Демо-шаблоны из `public/media/templates/` (генерация `scripts/generate.ts`) остаются для разработки; в мастере ткани **сначала** показываются импортированные ZIP-шаблоны, затем демо.

### 5.1. (ОТЛОЖЕНО) Принцип PSD
Мы **не рисуем** интерьеры сами. Админ или дизайнер загружает **готовый PSD-мокап** (покупной или бесплатный): спальня с кроватью, стол со скатертью, полотенце в ванной, курпача в комнате. В PSD есть smart object («Place your design here»). Система сама находит smart object, подставляет туда рисунок ткани, размноженный плиткой в нужном масштабе, и сохраняет готовый реалистичный макет. Тени, складки и свет берутся из самого PSD, ровно как если бы дизайнер делал это в Photoshop руками.

Итог: **1 раз** загрузили мокап, и **каждая** новая ткань автоматически получает макет на нём.

### 5.2. (ОТЛОЖЕНО) Загрузка PSD → шаблон (один раз на мокап)
1. **Загрузка** `.psd` до 500 МБ в Storage, с докачкой и прогрессом. Поддержку `.psb` проверить на spike (5.3).
2. **Анализ** (в Web Worker, библиотека `ag-psd`): дерево слоёв, поиск smart object-слоёв (`placedLayer`), их размер, трансформация (перспектива) и warp (деформация сеткой), маски и обтравочные слои.
3. **Экран «Разметка»**: превью мокапа, найденные smart object подсвечены рамками. Админ:
   - называет зоны: «Пододеяльник», «Подушка левая», «Подушка правая», «Простыня»;
   - отмечает, какие заполнять тканью (smart object с логотипом или биркой можно пропустить);
   - выбирает режим: **одна ткань во все зоны** или **разные** (основная + компаньон, на будущее).
4. **Калибровка размера**: для каждой зоны вводится реальный размер в см («пододеяльник 200 см по ширине»), из него считается `pxPerCm` для реального масштаба рисунка.
5. **Проверка совместимости**: система пишет, что в PSD не поддерживается (например «фильтр Displace на слое Shadow»), и показывает тестовый рендер шахматкой.
6. **Привязка**: шаблон привязывается к одному или нескольким изделиям («КПБ», «Пододеяльник»). Отмечается шаблон по умолчанию.
7. **Предрасчёт**: чтобы не открывать 300 МБ PSD на каждый рендер, при сохранении шаблона в Storage кладутся готовые слои: `background` (всё ниже smart object), `overlays[]` (всё выше: тени, блики, складки — с режимом наложения и прозрачностью), по каждой зоне: размер холста smart object, перспектива (8 чисел), warp-сетка, маска. Плюс `template.json` с этим описанием.

### 5.3. (ОТЛОЖЕНО) Движок рендера PSD: два варианта, spike (2 дня)
Перед этапом 3 Cursor делает **spike**: берём 3–5 реальных купленных PSD (кровать, скатерть, полотенце, курпача) и прогоняем оба варианта.

| | A. Photopea в скрытом iframe | B. Свой движок: `ag-psd` + WebGL |
|---|---|---|
| Как | Бесплатный онлайн-Photoshop, у него есть API: открыть PSD, заменить содержимое smart object скриптом, экспортировать JPG | Парсим PSD один раз (5.2), рендерим сами по предрасчитанным слоям |
| Точность | Как в Photoshop: warp, режимы наложения, корректирующие слои, стили | Хорошо для типовых мокапов. Не отрисуются smart filters (Displace), корректирующие слои, стили слоёв |
| Скорость | Медленно: 10–40 с на макет (тяжёлый PSD) | 1–2 с на макет, превью мгновенно |
| Зависимость | Внешний сервис; бесплатный режим с рекламой (без рекламы — платный аккаунт Distributor); замену smart object скриптом **подтвердить на spike** | Полностью ваш, работает без интернета-сервисов |
| Кода | Меньше | Больше (композитинг режимов наложения) |

**Рекомендация:** основной вариант **B** с проверкой совместимости при загрузке PSD. **A** — запасной для «сложных» мокапов, которые B не тянет. Если на spike A стабильно меняет smart object и скорость устраивает, можно начать с A, а B сделать позже.

**Рендер B по шагам:**
1. Для каждой зоны создать холст размера smart object и залить его плиткой рисунка с параметрами зоны (масштаб, сдвиг, поворот).
2. Деформировать холст в перспективу и warp-сетку зоны (WebGL, сетка треугольников).
3. Применить маску и обтравку.
4. Положить на `background`, сверху `overlays` с их режимами: normal, multiply, screen, overlay, soft light, linear burn, color dodge (обязательный минимум), прозрачность, маски слоёв.
5. Экспорт WebP 2000 px и 600 px в Storage.

### 5.4. Масштаб и подгонка на КАЖДОМ макете (ZIP и будущие PSD)
- **Стартовый масштаб** = реальный: `раппорт см × pxPerCm зоны`. Если раппорт не указан, рисунок встаёт так, чтобы по ширине зоны было ~4 повтора.
- Для **каждого выбранного макета** отдельно (и для каждой зоны отдельно, если включено «разные настройки зон») дизайнер настраивает:
  - **Масштаб от ×0.1 до ×10**: ползунок с логарифмической шкалой (точно и в мелком, и в крупном) + поле для ввода числа, шаг 0.05. Кнопки-пресеты ×0.5 / ×1 / ×2 / ×5 / ×10;
  - **сдвиг** по X и Y (перетаскиванием рисунка прямо на превью мышью или пальцем);
  - **поворот** 0–360° + кнопки 0° / 45° / 90°;
  - «**Сбросить к реальному размеру**» и «**Применить ко всем макетам**».
- Превью считается на уменьшенных слоях (1000 px) за доли секунды, финальный рендер 2000 px идёт при сохранении.
- Настройки хранятся в `fabric.mockups[].areas[]` и используются при пересборке, если шаблон обновили.

### 5.7. Шаблоны из фото: ZIP-пакет (основной формат)

Шаблоны готовятся вне системы из обычного фото интерьера (старый рисунок с ткани убран, свет и складки сохранены) и загружаются в систему **ZIP-архивом**. Система их **не создаёт**, а только импортирует и рендерит. Эталонная реализация рендера — `render.py` внутри каждого ZIP, TypeScript-версия должна давать тот же результат (сравнение с картинками из папки `out/` в ZIP).

#### 5.7.1. Состав ZIP
| Файл | Обязателен | Что это |
|---|---|---|
| `template.json` | да | Описание шаблона (ниже) |
| `background.jpg` | да | Фото интерьера целиком, размер = `size` |
| `mask_<zoneId>.png` | да, на каждую зону | 8 бит, 255 = ткань этой зоны, 0 = нет. При `softMasks: true` край мягкий (0..255 = доля ткани); маски при импорте **никогда не бинаризуются и не пережимаются** |
| `shade_<zoneId>.png` | да, на каждую зону | 8 бит, свет и складки белой ткани. Значение = `png / 255 * 1.5` (1.0 = обычный свет, >1 = блик) |
| `weave_<zoneId>.png` | только `finish: "sateen"` | Сила контраста «блестящая/матовая полоса». Значение = `png / 255 * 0.5` |
| `gloss_<zoneId>.png` | только `finish: "sateen"` | Сатиновые блики, `png / 255` (0..1) |
| `light_<zoneId>.png` | нет | Цвет освещения (тёплый/холодный), RGB, `png / 255 * 2` (1.0 = 128). Сохраняется как остальные слои и передаётся в рендер |
| `README.md`, `render.py`, `out/*.jpg` | нет | Описание, эталонный рендер, эталонные картинки для проверки |

#### 5.7.2. `template.json`
```json
{
  "name": "КПБ · страйп-сатин, спальня с изголовьем",
  "finish": "sateen",              // нет поля или "matte" = обычная ткань
  "size": [1374, 1145],            // ширина, высота background.jpg
  "units": "cm",
  "tint_bgr": [0.97, 0.99, 1.02],  // ВНИМАНИЕ: порядок B,G,R (OpenCV) — в RGB переставить
  "stripe": { "axis": "v", "photoPeriodCm": 2.5 },   // только у сатина
  "softMasks": true,               // необязательно: маски с мягким краем
  "shadeKnee": 1.35,               // необязательно: блики сжимаются только выше этого значения (по умолчанию 1.0)
  "highlightRolloff": true,        // необязательно: светлые ткани не выгорают в чистый белый
  "weaveCapable": true,            // необязательно: у matte-шаблона есть weave-слои, подходит и для тканых тканей
  "referenceColor": "#9bb1bc",     // необязательно: цвет ткани на исходном фото, для проверки
  "zones": [{
    "id": "duvet", "label": "Пододеяльник",
    "mask": "mask_duvet.png", "shade": "shade_duvet.png",
    "weave": "weave_duvet.png", "gloss": "gloss_duvet.png",   // только у сатина (weave — и у weaveCapable)
    "light": "light_duvet.png",    // необязательно
    "pxPerCm": 5.6,                // сколько пикселей фото на 1 см ткани (для антиалиасинга)
    "uvGrid": { "x0": 4, "y0": 540, "step": 8, "cols": 172, "rows": 72,
                "u": [ ... cols*rows чисел, см ... ],
                "v": [ ... cols*rows чисел, см ... ] }
  }]
}
```
`uvGrid` — координаты ткани в сантиметрах в узлах сетки. Узел (i, j) лежит в пикселе фото `(x0 + i*step, y0 + j*step)`, массивы построчно (`index = j*cols + i`). Ось `v` у сатина идёт поперёк полосок и повторяет изгибы складок.

#### 5.7.3. Импорт (админка → Шаблоны → «Импорт шаблона (ZIP)»)
1. Загрузка ZIP, распаковка в браузере (`jszip`).
2. Проверка: есть `template.json`; у каждой зоны есть mask и shade (у `weaveCapable` — ещё weave); размеры PNG = `size`; `u.length = v.length = cols*rows`. Ошибки показать списком по-русски.
3. Превью: фон + цветные маски зон с подписями `label`.
4. Админ выбирает изделия (productTypes), к которым привязать шаблон, и отмечает «по умолчанию».
5. Файлы сохраняются через `src/lib/storage.ts` в `templates/{templateId}/…`. В Firestore `templates/{id}` пишется `source: "zip"`, `engine: "uvgrid"`, `finish`, ссылки на файлы, зоны (без больших массивов `u/v` — они остаются в `template.json` в хранилище).

#### 5.7.4. Рендер (TypeScript, браузер, Canvas2D или WebGL) — точно как `render.py`
Реализация — готовый модуль `src/lib/mockup/uvgridRender.ts` из комплекта v2 (`kit/`), формулу не переписывать. Сверка с эталоном: `npx tsx scripts/uvgrid/parity-test.mjs` — все строки `OK` (среднее < 1, p99 ≤ 3 из 255). Слои шаблона подаются **полного размера** `template.size`; превью в мастере считается в Web Worker с `outputScale 0.4` (пауза 120 мс после ползунка), итоговый макет считается **в браузере** в том же Web Worker (до 2000 px, JPEG 0.92) и загружается в `/api/mockups/save`, где сервер только нарезает WebP 2000 / 1200 / 600 px. Тяжёлый расчёт на сервере не выполняется, поэтому админка не подвисает после публикации. Ошибки модуля (по-русски) показываются под превью. Заливка: `design` (рисунок), `stripes` (старые ткани из конструктора полос), `weave` (тканые ткани, 5.7.6).
Для каждой зоны по порядку из `zones` (поздняя зона перекрывает раннюю):
1. **Сетка → пиксели.** Билинейно растянуть `u`, `v` из `rows×cols` до `((cols-1)*step+1) × ((rows-1)*step+1)` и положить с позиции `(x0, y0)`, обрезав по краям фото.
2. **Подгонка дизайнера** (на макет или на зону, раздел 5.4): `scale` 0.1–10, `rot`°, сдвиг `du, dv` (см):
   `uu = (u+du)·cos − (v+dv)·sin`, `vv = (u+du)·sin + (v+dv)·cos`.
3. **Цвет ткани**:
   - *Рисунок дизайнера:* `pxcm = tileWidthPx / (rapportCm · scale)`; цвет = рисунок в точке `(uu·pxcm mod tileW, vv·pxcm mod tileH)`, билинейно, с повтором. Если `pxcm / pxPerCm > 1.6` — сначала размыть рисунок (σ = 0.4·pxcm/pxPerCm) или взять mip-уровень, иначе будет муар. `band = 0`.
   - *Генератор страйпа (только `finish: "sateen"`):* полосы `[{ширина см, цвет, блестящая: да/нет}]`, период `P = сумма ширин`. `t = (vv / scale) mod P`, найти полосу, край полосы сгладить на `aa = 0.6 / (pxPerCm·scale)` см. `band = +1` для блестящей, `−1` для матовой.
4. **Свет:** `s = shade·1.5/255`; если `s > 1`, то `s = 1 + (s − 1)·0.55`.
5. **Плетение сатина:** `w = weave·0.5/255`; множитель `1 + 1.0 · w · band` (контраст 1.0 — настраиваемый).
6. **Зерно ткани:** шум N(0,1), размытый σ 0.7 px, амплитуда 0.02 (matte) или 0.008 (sateen).
7. `fabric = цвет × s × плетение × зерно × tint` (tint в RGB!), обрезать 0..1.
8. **Блеск (sateen):** `g = gloss/255 · 0.35 · (0.6 + 0.4·max(band, 0))`; `fabric = 1 − (1 − fabric)·(1 − g·[1.0, 0.98, 0.97])`.
9. **Сведение:** `a` = объединение масок, размытое σ ≈ 1 px; `итог = background·(1 − a) + fabric·a`.
10. Экспорт WebP 2000 px и 600 px → хранилище → `fabric.mockups[]`.

#### 5.7.5. Связь с остальной системой
- Шаблоны из ZIP и из PSD выглядят в админке одинаково: в мастере ткани (7.3, шаг 3) они показываются по изделию, настройки масштаба, сдвига и поворота работают одинаково.
- Тканые ткани (страйп-сатин, жаккард, дамаск) заводятся в режиме «Тканый рисунок» (5.7.6). Прежний «Конструктор полосок» и генерация картинки из полос удалены.
- Готовые ZIP: `kpb_template_package.zip` (КПБ, обычная ткань), `stripe_sateen_template.zip` (КПБ, страйп-сатин), `kpb_plain_template.zip` (КПБ, однотонное — обычные и тканые ткани, мягкие маски, слои света). Новые ZIP добавляются по мере появления фото интерьеров.

#### 5.7.6. Тканые ткани: страйп-сатин, жаккард, дамаск (режим `weave`)
Узор у таких тканей — переплетение и блеск, а не печать, поэтому фото ткани плиткой на макет не кладётся.
- **Справочник типов ткани** (Настройки → Типы ткани): признак «тканый рисунок» (`fabricType.woven`). По умолчанию включён у страйп-сатина, жаккарда, дамаска. Это только подсказка в форме: если тип тканый, а галочка не стоит, под галочкой появляется напоминание.
- **Форма ткани:** галочки нет — ткань тканая, если создана в разделе «Жаккардовые» (`kind: 'woven'` → `fabric.woven = true`). Выбор типа ткани макеты не меняет. Поле рисунка называется «Фото ткани». Раппорт и «бесшовный» не показываются. **Варианты цвета** есть: у каждого своё фото ткани и свой цвет для макетов (`variant.weaveColor`, определяется по фото, можно поправить); узор переплетения общий.
  - **Цвет ткани:** по умолчанию `pickFabricColor(фото)`; пипетка — клик по фото; выбор цвета вручную; кнопка «Определить по фото»; ползунок «светлее / темнее» (correction 0.8–1.4).
  - **Узор переплетения:** «Полосы» — список `{ширина см, блестящая}`, пресеты 0.5+0.5, 1+1, 1.25+1.25, 2+2, 3+1 см; «Схема жаккарда» — ч/б картинка (белое = блестящее) + ширина раппорта, см; «Без узора» — гладкий сатин.
  - Хранение: `fabric.weave = { color, correction, pattern: 'stripes'|'map'|'none', stripes?, mapUrl?, mapWidthCm? }`.
- **Макеты:** только шаблоны с `finish: "sateen"` или `weaveCapable: true` (например «КПБ · однотонное, светлая спальня»), остальные серые с подписью «для тканых тканей не подходит». Заливка `{ kind: 'weave', color, stripes | map + mapWidthCm }`; масштаб, поворот (90° = вертикальная полоса), сдвиг — как обычно.
- **Каталог:** фото ткани (`design.webUrl`) — в карточке и в окне дизайна на вкладке «Ткань». Отдельных строк «Цвет» и «Узор» в характеристиках нет: цвет образца не подписывается, для крашеных тканей работает переключатель тонов (6.3).

### 6.4. Панель управления журналом (низ экрана, как в примере, но лучше)
| Элемент | Действие |
|---|---|
| ⊞ Миниатюры | Сетка всех страниц, переход по клику |
| 🔍 Поиск | По названию, артикулу, цвету. Результат открывает окно дизайна |
| ‹ 6–7 / 24 › | Номер разворота, стрелки |
| Полоса прогресса | Перетаскивание = быстрый переход |

| ⤢ Полный экран | |
| ↗ Поделиться | Копировать ссылку, QR-код, ссылка на текущую страницу |

| ✉ Заявка | Форма: имя, телефон/Telegram, комментарий, выбранные дизайны |

Иконки — Lucide SVG, без эмодзи (в таблице эмодзи только для наглядности).

### 6.5. Поведение
- **ПК**: разворот из двух страниц, перелистывание кликом по краю, стрелками ←/→, перетаскиванием угла.
- **Телефон (портрет)**: одна страница, свайп. Панель сворачивается в 4 кнопки (миниатюры, страницы, язык, ещё…).
- **Глубокие ссылки**: `/c/{slug}#p12` открывает 12-ю страницу, `/c/{slug}/d/{art}` открывает окно дизайна.
- **Превью ссылки** в Telegram/WhatsApp/Instagram: обложка 1200×630 + название + «N дизайнов» (Next.js `generateMetadata` + OG-картинка).
- **Скорость**: первая страница видна < 1.5 с на 4G. Картинки WebP через `srcset` (600/1200/2000), подгрузка ±2 разворотов вокруг текущего, остальное лениво.
- **Корзина образцов** (по желанию в v1.1): «♡ в заявку» на дизайне, внизу счётчик, одна заявка на несколько дизайнов.
- `prefers-reduced-motion` отключает анимацию листания (обычная смена страниц).
- Доступность: фокус виден, Esc закрывает окно, у картинок `alt` = название + изделие.

### 6.6. Стиль
- Светлая тема по умолчанию (бумага, много воздуха), тёмная — опция каталога (для Fashion).
- Шрифты с кириллицей и узбекской латиницей: заголовки **Prata** или **Tenor Sans**, текст **Manrope**, цифры и артикулы **JetBrains Mono**.
- Фирменные акценты: глубокий синий хорезмской майолики + золото. Цвет фона страниц не чисто белый, а слегка тёплый «бумажный» серый.

## 7. Админка (UI/UX сотрудников)

### 7.1. Навигация
`Ткани` · `Каталоги` · `Заявки` · `Статистика` · `Шаблоны макетов` (админ) · `Справочники` (изделия, типы тканей, глоссарий) · `Пользователи` (админ)

### 7.2. Список тканей
- **Три раздела** вкладками сверху: **Жаккардовые**, **Однотонные**, **Рисунок** (с количеством). Кнопка «Добавить …» создаёт дизайн того раздела, где вы находитесь, — форма сразу настроена под него, никаких галочек. Старые ткани разложены автоматически: тканые → Жаккардовые, с тонами → Однотонные, остальные → Рисунок.
- Плитка или таблица (переключатель). Фильтры: коллекция, тип ткани, изделие, статус, новинки, «без перевода», «без макетов».
- Массовые действия: опубликовать, в архив, пересобрать макеты, добавить в каталог.
- Карточка в списке: превью рисунка, артикул, название, статус-чип, значки изделий.

### 7.3. Создание ткани — мастер из 4 шагов (с автосохранением черновика)
1. **Рисунок**: перетащить файл (до 50 МБ). Сразу показываются превью, размер в px, вопрос «рисунок бесшовный?», поле «раппорт, см», автоматически извлечённые 3–5 цветов.
   **Варианты цвета** (необязательно): название основного цвета и сколько угодно вариантов — для каждого свой файл рисунка и название цвета. Раппорт, бесшовность и настройки макетов общие с основным рисунком. После «Сохранить и опубликовать» макеты для каждого варианта строятся в фоне в браузере (5.7.4) и сохраняются по одному; на кнопке видно «Собираем макеты 2 из 3…». Пока идёт сборка, вкладку нельзя закрывать или перезагружать (браузер предупредит), переходить по разделам админки можно. «Сохранить макет WebP» под макетом сохраняет его сразу для основного рисунка и всех вариантов / тонов. Если сохранение не прошло (нет интернета), кнопка снова активна и показывается сообщение.
   Форма зависит от раздела. **Рисунок** — как описано выше (раппорт, стык, варианты цвета рисунка, макеты на каждый вариант). **Жаккардовые** — фото ткани, цвет и узор переплетения (5.7.6), варианты цвета с макетами на каждый.
   **Однотонные — три тона**: первым идёт блок «Фото ткани — три тона» — «Светлый тон», «Средний тон» (это основное фото), «Тёмный тон». Все три обязательны: пока какого-то нет, «Сохранить и опубликовать» недоступна и рядом написано, какого тона не хватает. С каждого фото берётся цвет тона (можно поправить); на макеты ложится этот сплошной цвет, макеты строятся для каждого тона на любых шаблонах. Поле «Отделка» — только подпись и на тона не влияет.
2. **Данные**: название, артикул (проверка уникальности на лету), **коллекция** и **тип ткани** (выпадающие списки с поиском и пунктом «＋ Добавить новый…» — см. 7.6), **плотность и ширина — обычные текстовые поля, дизайнер пишет сам** (`120`, `120–125`, `150 / 220 / 240`; под полем серая подсказка формата, система сама разбирает числа для фильтров), состав (текст с подсказками частых вариантов), **отделка** (выпадающий список из справочника `finishes` с «＋ Добавить новый…»), описание, теги.
3. **Применение и макеты**: галочки изделий (тоже с «＋ Добавить изделие…»). При выборе типа ткани подсказки ставятся автоматически («Вафельное полотно» → «Полотенце», «Кухонное полотенце»). Под каждым отмеченным изделием — карточки шаблонов (сначала ZIP, затем демо), можно выбрать один или несколько. **Каждый выбранный макет настраивается отдельно** (раздел 5.4):
   ```
   ┌ КПБ · Спальня светлая ─────────────────────────────┐
   │ [ большое живое превью — рисунок можно тянуть мышью ] │
   │ Зона: ( Все зоны ▾ ) / Пододеяльник / Подушки         │
   │ Масштаб  ×0.1 ──────●────────── ×10   [ 2.40 ]        │
   │          [×0.5] [×1] [×2] [×5] [×10]                  │
   │ Поворот  [0°] [45°] [90°]  ○ 0°                       │
   │ [Сбросить к реальному размеру] [Применить ко всем]    │
   └──────────────────────────────────────────────────────┘
   ```
4. **Перевод и публикация**: RU слева, EN и UZ справа (автоматически), правка руками, кнопка «Перевести заново». Чек-лист готовности: ✓ рисунок ✓ раппорт ✓ хотя бы 1 макет ✓ перевод. Кнопки «Сохранить черновик» / «Опубликовать».

После публикации ткань **сама** появляется во всех каталогах, чьи правила ей подходят. Тост: «Опубликовано. Попало в каталоги: Евро — сатин, Новинки осень».

### 7.4. Конструктор каталога
- Слева настройки: название (RU, перевод авто), slug, языки, режим «по правилам / вручную», правила-фильтры, **какие изделия показывать на макетах**, тип страницы (1/2/3/4 дизайна), разделы, тема, цены вкл/выкл, доступ (публичный / по ссылке / PIN), срок действия.
- В ручном режиме ткани добавляются из списка и перетаскиваются для сортировки.
- Справа **живое превью журнала** (тот же компонент, что видит клиент).
- Кнопки: «Опубликовать», «Скопировать ссылку», «QR-код (PNG)», «Скачать PDF».
- Готовые пресеты в один клик: «Курпача», «Евро коллекция», «Fashion», «Полотенца и кухня», «Новинки сезона».
- **Быстрое создание**: «＋ Новый каталог» → ввести только название («Курпача для Самарканда») → каталог создан сразу (slug по транслиту, перевод названия автоматически, режим «вручную», пустой). Дальше добавляются ткани или включаются правила.

### 7.7. Шаблоны макетов (только админ)
- Список импортированных ZIP-шаблонов: превью, категория интерьера, изделия, движок `uvgrid`, `finish` (matte / sateen).
- **«Импорт шаблона (ZIP)»** — единственный способ добавить новый шаблон (5.7.3): загрузка ZIP, проверка, превью зон, привязка к изделиям, сохранение в Storage + Firestore.
- Редактор PSD (5.6) и страница `/admin/lab/psd` **не в меню**, отложены.

### 7.5. Заявки и статистика
- Заявки: таблица со статусами, фильтр по каталогу, ссылка на дизайн. Каждая заявка **сразу уходит в Telegram-чат** отдела: каталог, дизайн(ы), имя, контакт, язык.
- Статистика по каталогу: открытия, уникальные посетители, среднее число страниц, **топ-10 дизайнов по открытиям**, зумы, заявки, конверсия «открыл → заявка». Это показывает дизайнерам, какие рисунки реально цепляют.

### 7.6. Справочники: добавлять новое самим
Раздел `Справочники` с вкладками: **Коллекции**, **Типы тканей**, **Изделия (применение)**, **Отделка** (только подпись). Плюс быстрый способ прямо из формы ткани: в любом выпадающем списке последний пункт «＋ Добавить новый…» открывает мини-окно.

| Справочник | Поля мини-окна | Что происходит после сохранения |
|---|---|---|
| Коллекция | Название RU (EN/UZ автоматически), порядок | ☑ «Сразу создать каталог этой коллекции» (включено по умолчанию): создаётся каталог `/c/{slug}` с правилом «коллекция = эта». Новые ткани коллекции попадают туда сами |
| Тип ткани | Название RU, какие изделия подсказывать | Появляется в форме и фильтрах каталогов |
| Отделка | Название RU | Появляется в поле «Отделка» и в характеристиках |
| Изделие | Название RU, для каких типов ткани подсказывать | Появляется в галочках «Применение». Пока к изделию нет шаблона макета, метка «нет мокапа» и ссылка «Импорт шаблона (ZIP)» (только админ) |

Порядок в списках меняется перетаскиванием. Используемые элементы можно только скрыть, не удалить.
